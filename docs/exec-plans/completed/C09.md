# C09 — PREVRANDAO Value-Dependency Replacement

Status: Complete

Owner: ArcReady maintainers

Decision record: `docs/research/C09-D.md`

Implementation closeout: `docs/exec-plans/completed/C09A.md`

Completed: 2026-08-18

## 1. Product problem

ArcReady previously exposed two default-critical rules for one underlying Arc
compatibility problem:

```text
wallet/PREVRANDAO_NOT_SUPPORTED
bridge/NO_PREVRANDAO_RELAY_SELECTION
```

The former implementations relied on broad Arc/PREVRANDAO keyword proximity and
blanket `mixHash` matching. That evidence could not prove that PREVRANDAO affected
a supported behavior or that the exact contract was associated with Arc.

C09 replaced that evidence model rather than hardening the old heuristics.

## 2. Research result

C09-R1 through C09-R3-B established a bounded, fail-closed implementation path:

- exact PREVRANDAO source evidence can be owned to concrete Solidity
  contract/function ranges;
- direct and one reviewed local binding can be traced to approved same-function
  behavior sinks without building a general data-flow platform;
- comments, strings, mutation, ambiguity, unsupported syntax, and wider flow can
  fail closed;
- one exact Foundry `forge script` broadcast artifact family can associate a
  concrete contract with Arc Testnet without live RPC or explorer calls.

The research did not authorize general Solidity analysis, broad deployment
framework support, or live-chain claims.

## 3. Decision

C09-D selected **Build** with this architecture:

- one shared private analyzer;
- two temporary compatibility shells preserving the existing public IDs;
- no new runtime `solidity` preset or public finding category;
- exactly one shell owner for each eligible private record;
- public critical emission only when supported source/value evidence and exact
  Foundry Arc ownership are both proven for the same concrete contract;
- preserve inventory `19 known / 16 default / 7 wallet / 4 canonical`;
- keep both rules non-canonical FindingV2 rules.

## 4. Implementation result

C09A completed the selected Build path in E1 through E5.

Merged implementation phases:

- E1 / PR #63 — private Solidity parser/source analysis;
- E2 / PR #65 — bounded dependency, sink, routing, and cache behavior;
- E3 / PR #68 — Foundry ownership and composed eligibility;
- E4 / PR #67 — public compatibility-shell migration.

The final implementation removes broad keyword emission, preserves public IDs and
preset behavior, and emits only source-scoped findings backed by the reviewed
bounded evidence contract.

Full implementation and closeout details are maintained in:

```text
docs/exec-plans/completed/C09A.md
docs/research/C09A-E5.md
```

## 5. Final limitations

C09/C09A intentionally do not add:

- general Solidity CFG, SSA, taint, symbolic execution, or vulnerability
  analysis;
- unrestricted cross-file, cross-contract, import, inheritance, or mutation
  resolution;
- Hardhat or generic deployment-framework support;
- live RPC, explorer, deployed-bytecode, runtime, or transaction-success
  verification;
- a new public rule ID, preset, category, schema, or canonical rule.

Foundry `run-latest.json` is retained static artifact evidence only.

## 6. Compatibility follow-up

The wallet and bridge public IDs remain temporary compatibility shells. A later
reviewed milestone may consolidate or retire them only when concrete usage or
compatibility evidence justifies the migration.

The next sequenced engineering milestone after C09A closeout is C10: versioned
App Kit compatibility.
