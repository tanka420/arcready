## 1. Product brief

### Problem

`wallet/NO_ETH_GAS_LABEL` is a default critical regex that cannot prove its
matched line is rendered Arc wallet UI. It converts valid Gwei calculations and
correct `not ETH` explanations into compatibility blockers.

### Why now

The pinned C11 adoption audit found seven critical findings in one real
repository: six definite false positives and one mixed file. The rule alone
drove that repository to score zero. Current first-party documentation also
uses Gwei legitimately outside rendered wallet denomination.

### Product value

Default ArcReady scans stop failing or degrading reports on unsupported UI
inference. Users who deliberately want the legacy heuristic can still opt in as
low-confidence advice through the existing rule-level configuration.

## 2. Decision and risk

Decision: Advice-only migration.

This is R3 because default selection, severity, report score, status, `failOn`,
and CLI exit behavior intentionally change. The public rule ID, configuration
schema, reporter schemas, and package exports remain compatible.

## 3. Premise and uncertainty

Verified 2026-08-20:

- Arc wallet guidance requires user-facing fees in USDC/USD, not Gwei/ETH;
- Arc wallet and custody guidance use Gwei for valid internal EIP-1559 fee
  units and calculations;
- the current detector proves only file-level text and coarse Arc co-location;
- the adoption corpus demonstrates default false-positive harm;
- the C08A private default-excluded mechanism is implemented and tested.

Uncertainty deliberately remains around framework-specific rendered UI flow.
C12 does not describe unmatched or unsupported code as safe.

## 4. Supported and unsupported surface

### Supported

- preserve public `noEthGasLabelRule` and `walletRules` known inventory;
- exclude the rule from the private default wallet preset;
- intentionally change exported `getRulesForPresets(["wallet"])` and
  `defaultPresetRegistry` to return that default subset;
- select it exactly once for explicit `info`, `warning`, or `critical` config;
- keep missing, `off`, and unknown IDs non-selecting;
- keep custom preset registries isolated;
- preserve existing detector matches for explicit/direct execution;
- change direct/default severity and policy to deprecated `info` advice;
- update finding copy, remediation, catalogs, inventory assertions, and public
  documentation to the new contract.

### Unsupported

- proving JSX/TSX render sinks or visible DOM output;
- linking text across imports, components, props, helpers, or files;
- distinguishing every internal Gwei calculation from user copy;
- multichain ownership, localization, template composition, or runtime UI;
- certifying that an opted-in finding is a real defect.

### Non-goals

- no regex widening or phrase-specific ArcLens patch;
- no new analyzer, parser, shared framework, config key, rule ID, or preset;
- no FindingV2/canonical promotion;
- no reporter/schema, dependency, package-export, or scoring-weight change;
- no immediate public-ID removal;
- no changes to other default-excluded rules.

## 5. Architecture spike and decision

### Spike

The ignored selection probe ran the affected rule across 151 pinned ArcLens
source files. Current default behavior produced seven critical findings, score
zero, and fail status. Simulated default exclusion produced no finding and pass 100. Explicit `info` preserved seven review records with score 86 and pass
status. Explicit `critical` preserved legacy enforcement.

Existing C08A selection plus preset/wallet tests passed `228/228` before
production editing.

### Options considered

- severity-only default execution: rejected because false findings remain in
  ordinary reports;
- more regex exclusions: rejected because rendered ownership remains unproven;
- new rendered-UI analyzer: deferred as a separate evidence-led milestone;
- immediate retire: rejected for the compatibility period;
- existing private default-excluded path: selected.

### Chosen approach

1. create a private default wallet subset excluding exactly this rule;
2. append the public rule to the existing private excluded-rule list after the
   current attestation advice rule;
3. reuse the unchanged top-level explicit selection contract;
4. change direct severity to `info` and make copy conditional/review-only;
5. align catalog policy to deprecated, default-excluded advice;
6. prove the intentional default inventory, score, status, and exit delta.

Approved copy candidate:

```text
description: Provides low-confidence advice when a file with Arc evidence also contains a gas or fee line mentioning ETH or Gwei.
message: Gas or fee text mentioning ETH/Gwei is co-located in a file with Arc evidence; review whether the text is a user-facing Arc fee label.
remediation: If this text is rendered to Arc wallet users, display the fee in USDC or USD. Gwei remains valid for internal gas-price units and calculations; correct contrasts, documentation, and non-Arc content may not require changes.
```

### Stop conditions

Use the stop conditions in C12-R1. Any need for a public registry, detector
widening, JSX analysis, schema change, or unrelated fixture mutation pauses the
milestone for scope cut or redesign.
