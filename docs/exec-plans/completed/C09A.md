## 1. Goal

Replace the two broad PREVRANDAO keyword heuristics with one production private
analyzer that emits only when both reviewed evidence layers are proven:

1. bounded Solidity source, same-function value dependency, and supported sink;
2. exact retained Foundry contract-to-Arc deployment association.

Retain the existing wallet and bridge public IDs as temporary compatibility
shells without adding a new runtime preset, finding category, or public ID.

## 2. Final architecture

C09A delivers one shared private analyzer with scan-scoped reuse. It owns lazy
Solidity parser loading, bounded source/function ownership, direct and approved
one-binding value flow, supported sink classification, deterministic shell
routing, Foundry broadcast association, and composed eligibility.

The public compatibility shells are:

```text
wallet/PREVRANDAO_NOT_SUPPORTED
bridge/NO_PREVRANDAO_RELAY_SELECTION
```

Each private eligible record has exactly one shell owner. Selecting both presets
does not duplicate one underlying record.

The old broad PREVRANDAO and blanket `mixHash` keyword emission path was removed
in E4.

## 4. Final dependency contract

Production dependency:

```text
@solidity-parser/parser@0.20.2
```

The reviewed dependency is MIT licensed with zero runtime transitive dependencies
in its package metadata. ArcReady does not add `solc`, `solc-js`, Tree-sitter,
a Foundry binary, or another Solidity parser in C09A.

Package smoke verifies parser externalization and provenance, declaration type
isolation, packed-artifact boundaries, lazy loading, dependency withdrawal and
restoration, and installed-package execution.

## 5. Supported evidence boundary

A reportable record requires all of the following within the reviewed bounded
surface:

- supported complete `.sol` input;
- exact supported PREVRANDAO source form;
- same-function bounded value dependency;
- approved behavior sink;
- exact concrete contract identity;
- deterministic shell owner;
- exact retained Foundry broadcast evidence;
- Arc Testnet chain ID `5042002`;
- valid exact deployed address;
- no ambiguous or conflicting ownership.

Unsupported or ambiguous evidence fails closed.

## 6. Explicit non-goals and limitations

C09A does not provide general:

- Solidity CFG, SSA, taint, symbolic execution, or vulnerability analysis;
- cross-file or cross-contract value resolution;
- arbitrary inheritance, modifier, library, import, mutation, alias, loop, or
  recursion analysis;
- generic Yul analysis;
- compiler-version inference;
- Hardhat or custom deployment adapters;
- live RPC, explorer, bytecode, transaction, or runtime verification.

Foundry evidence is retained static artifact evidence only. A finding does not
claim that a deployment is live, bytecode matches current chain state, or a
transaction succeeded.

## 7. Compatibility period

Both public rule IDs remain default-critical and non-canonical during the
compatibility period.

A later separately reviewed milestone may consolidate or retire the shells only
from concrete compatibility or usage evidence. C09A itself does not add a new
`solidity` preset, public category, public rule ID, schema, or canonical
FindingV2 rule.
