# C11 — Arc Chain Hexadecimal Identity Correction

Status: Ready for publication

Risk class: R2 local rule correction

Owner: ArcReady maintainers

Base branch: `main`

Base SHA: `17e75263388374ad1e90cf52812fc38297b2802a`

Last reviewed: 2026-08-20

Research record: `docs/research/C11-R1.md`

## 1. Product problem

ArcReady accepts and recommends `0x4CF4B2` as the EIP-3085 hexadecimal form of
Arc Testnet chain ID `5042002`. The values are not equal. Live Arc Testnet RPC,
integer conversion, current real-repository use, and ArcReady's own C07
transaction analyzer agree that the correct value is `0x4CEF52`.

This can both hide a broken wallet configuration and give a developer a broken
remediation. The defect is exact, current, and directly actionable.

## 2. Decision and architecture

Decision: Fix as a bounded local defect.

Keep the existing `wallet/ARC_CHAIN_METADATA` analyzer and public contract.
Remove only the incorrect value alias, correct remediation text, and add the
smallest representative regressions. Because the alias lives in the shared
chain-object scanner, explicitly correct its false Arc-ownership effect on
`wallet/WALLET_NATIVE_USDC_DISPLAY` as well.

The candidate data path remains:

```text
supported Arc-owned chain object
→ direct id or chainId literal
→ normal integer parsing
→ exact comparison with 5042002n
→ existing metadata and native-currency consumers
```

No new shared infrastructure, resolver, AST family, rule ID, or public schema is
needed.

## 3. Supported change

Production and contract changes are limited to:

- delete the special case that maps `0x4cf4b2` to `5042002n`;
- change legacy remediation to `0x4CEF52`;
- change FindingV2 remediation to `0x4CEF52`;
- change the rule catalog example to `0x4CEF52`;
- stop treating the non-Arc `0x4cf4b2` value as sole Arc ownership in the
  shared native-display consumer.

Regression changes are limited to:

- replace safe string/numeric hex examples with `0x4CEF52`/`0x4cef52`;
- add string and numeric `0x4CF4B2` incorrect-ID cases;
- replace native-display positive hexadecimal controls with `0x4CEF52`;
- add generic wrong-hex native-display non-findings;
- add strongly Arc-owned wrong-ID plus wrong-native-currency cases;
- add combined wallet execution expectations for finding count, order, score,
  status, and exit;
- update exact FindingV2 remediation expectations;
- retain all existing ambiguous, malformed, endpoint, ordering, and
  deterministic-result tests.

## 4. Non-goals

C11 does not:

- add new ownership evidence or change the analyzer's lexical grammar;
- change default severity, presets, inventory, ordering, score weights, or exit
  policy;
- change canonical eligibility, FindingV2 schema, or reporter behavior;
- add live RPC calls to production;
- change `NO_ETH_GAS_LABEL` or implement its existing Advice-only decision;
- broaden C07 transaction submission analysis;
- change any other chain, endpoint, or currency rule.

## 6. Architecture and correction policy

This is correction-policy class A: one wrong constant is special-cased despite
normal parsing already supporting the correct value. No missing analyzer
contract class or architecture redesign is required.

Architecture review must verify the official/live value conflict, the exact
integer equivalence, both shared scanner consumers, public remediation and
combined-wallet impact, and the strict separation from the existing gas-label
Advice-only decision before production editing.

## 8. Boundary impact

Intended impact:

- one exact wrong hexadecimal ID changes from silent to the existing critical
  incorrect-ID finding;
- a generic object whose sole Arc evidence was that non-Arc value loses the
  current false native-display finding;
- an independently Arc-owned object retains supported metadata and
  native-currency findings, with combined order, score, status, and exit locked;
- remediation changes from a wrong hexadecimal value to the exact live value;
- all other supported, unsupported, and public boundaries remain unchanged.

Inventory remains `19 known / 16 default / 7 wallet / 4 canonical`.
