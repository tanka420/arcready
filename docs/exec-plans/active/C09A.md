## 1. Goal

Replace the two existing PREVRANDAO keyword heuristics with one production
private analyzer that emits only when both of these evidence layers are proven:

1. bounded Solidity source, same-function value dependency, and supported sink;
2. exact Foundry contract-to-Arc deployment association.

Retain the two existing public rule IDs as temporary compatibility shells without
adding a new runtime preset, finding category, or public ID.

## 2. Current state

Current public rules:

```text
wallet/PREVRANDAO_NOT_SUPPORTED
bridge/NO_PREVRANDAO_RELAY_SELECTION
```

Both are default critical and both currently rely on broad Arc text plus
line-level PREVRANDAO or `mixHash` matching. The bridge rule adds same-line relay
or randomness words.

C09 research established:

- blanket `mixHash` equivalence is unsupported;
- symbol presence does not prove behavior;
- R3-A source/value analysis is feasible within a bounded grammar;
- R3-B exact Foundry Arc ownership is feasible for one artifact family;
- no production parser dependency or behavior has yet been introduced.

## 3. Target architecture

### Shared analyzer

Create one private analyzer with a scan-scoped cache. It owns:

- lazy parser loading;
- supported `.sol` discovery;
- AST parse and diagnostics;
- source and function ownership;
- bounded binding and sink classification;
- concrete contract identity;
- Foundry broadcast discovery and parsing;
- exact contract-to-chain association;
- private record composition and deterministic ordering.

The analyzer returns private records only. It must not import public finding or
reporter types.

### Compatibility shells

The existing wallet and bridge rule modules become thin adapters.

They may:

- request the shared private records;
- filter records by the reviewed shell ownership class;
- convert each owned record into the existing public Finding shape;
- apply existing config severity overrides through normal runtime execution.

They must not:

- parse source independently;
- re-run Foundry association independently;
- contain PREVRANDAO or `mixHash` keyword detection;
- emit the same private record twice;
- borrow Arc ownership from broad text.

## 4. Private record contract

Each reportable private record must include enough evidence for deterministic
conversion and review:

```text
sourceFile
contractName
functionName
sourceKind
sourceOffset
bindingKind
sinkKind
sinkOffset
shellOwner
foundryArtifactPath
chainId
contractAddress
confidence
```

The record must not claim runtime behavior, transaction success, deployed bytecode
identity, or live-chain verification.

### Shell ownership

Allowed values:

```text
bridge-relay
wallet-compatibility
```

`bridge-relay` requires a supported sink whose exact function, collection, or
selected-entity identifiers establish relay, relayer, validator, sequencer, or
committee behavior.

`wallet-compatibility` owns the remaining supported selection, authorization,
eligibility, winner, recipient, allocation, and ordering records during the
compatibility period.

Ambiguous shell ownership fails closed and emits no public finding.

## 5. Dependency and packaging contract

C09A-E1 may add exactly:

```text
@solidity-parser/parser@0.20.2
```

as a production dependency only after the dependency review passes.

Required dependency checks:

- exact version and integrity are recorded in `pnpm-lock.yaml`;
- package license is MIT-compatible;
- installed and packed contents are measured;
- zero runtime transitive dependencies are confirmed;
- Node 22 import succeeds;
- tsup ESM build and declaration generation succeed;
- packed ArcReady package can lazy-load the parser;
- non-Solidity scans do not import the parser;
- no `solc`, `solc-js`, Tree-sitter, Foundry binary, or additional parser is
  introduced.

The parser should remain external to the main tsup bundle only when the packed
package includes and resolves it correctly. Bundling or externalization must be
decided from package smoke evidence, not assumption.

## 6. Supported source grammar

The first production version supports only R3-reviewed complete `.sol` source
families.

### Source forms

- exact `block.prevrandao`;
- one approved direct cast around the source;
- one same-function single-assignment local binding;
- exact inline assembly `prevrandao()` assignment;
- `block.difficulty` only after a separately reviewed exact post-Paris EVM-target
  evidence adapter exists.

`block.difficulty` should remain disabled in E1–E4 unless that adapter is
implemented and independently reviewed within the same bounded milestone.

### Supported sinks

- direct modulo/index collection selection;
- approved direct relay, validator, sequencer, committee, winner, recipient,
  allocation, authorization, eligibility, and ordering expressions;
- same function and same contract only;
- deterministic earliest reportable candidate when multiple source occurrences
  exist.

### Safe observations

The analyzer must not report:

- unused reads;
- diagnostic returns;
- logs or event-only observations;
- explicit zero compatibility assertions;
- hashing without a supported behavior sink;
- deterministic replacement logic.

## 7. Foundry ownership contract

Supported artifact family:

```text
broadcast/<Script>.s.sol/<chainId>/run-latest.json
```

Required evidence:

- normalized repository-relative paths;
- same bounded project root for `src/` and `broadcast/`;
- no empty, dot, parent, absolute, backslash, vendor, or sibling-root paths;
- integer path chain ID;
- integer JSON `chain` field equal to the path chain ID;
- exact concrete contract definition outside comments and strings;
- exactly one concrete definition for the deployed contract name;
- `CREATE` transaction;
- valid 20-byte deployed address;
- exact Arc Testnet chain ID `5042002`;
- no conflicting non-Arc deployment for the same exact contract;
- no conflicting Arc addresses.

Malformed, incomplete, fuzzy, duplicate-owner, conflicting, unsupported-adapter,
or absent evidence emits no public finding.

C09A does not execute `forge` and does not query RPC or explorers.

## 8. Implementation phases

### C09A-E1 — dependency and private parser source records

Scope:

- complete the dependency and packaging review;
- add the exact approved parser dependency if all gates pass;
- implement lazy parser loading;
- parse only `.sol` candidates;
- recognize exact source forms and source ownership;
- return private source records only;
- keep both public rules behavior unchanged until E4.

Required tests:

- exact package/version/integrity assertions;
- parser load and lazy-load instrumentation;
- comments, strings, abstract contracts, malformed syntax, unknown nodes, and
  missing ranges fail closed;
- R3-A canonical and adversarial source corpus is ported or reused without
  weakening expected classifications;
- package build and packed-package smoke pass.

Exit:

- independent review `APPROVE` with 0 blocker / 0 major / 0 minor;
- no public finding change.

### C09A-E2 — bounded binding, sink, and shell routing

Scope:

- implement direct and one single-assignment local flow;
- implement approved same-function sinks;
- classify safe observations and unsupported flow;
- assign exactly one reviewed shell owner;
- maintain deterministic source and sink offsets;
- return private records only.

Required tests:

- direct, cast, one-binding, assembly, safe, unsupported, and adversarial cases;
- mutation, shadowing, duplicate declarations, joins, loops, cross-function,
  cross-contract, unsupported Yul, and ambiguous shell ownership fail closed;
- bridge and wallet shell-routing corpus;
- repeated analyzer request in one scan returns the same cached records;
- no public finding change.

Exit:

- independent review `APPROVE` with 0 blocker / 0 major / 0 minor.

### C09A-E3 — Foundry adapter and composed eligibility

Scope:

- implement the reviewed Foundry JSON adapter;
- prove exact project-root, concrete contract, chain, transaction, and address
  ownership;
- compose R3-A-style source records with R3-B-style Arc ownership;
- mark private records eligible only when both layers match the same exact
  contract and project root;
- still emit no public findings.

Required tests:

- 16 canonical project cases;
- 9 ownership adversarial cases;
- malformed JSON, duplicate definitions, abstract-only source, comment/string
  spoofing, missing address, non-CREATE, conflict, sibling root, vendor, and
  traversal pressure;
- source record for one contract cannot borrow another contract's artifact;
- source project cannot borrow a sibling project's artifact;
- no public finding change.

Exit:

- independent review `APPROVE` with 0 blocker / 0 major / 0 minor.

### C09A-E4 — compatibility shells and public migration

Scope:

- delete the keyword detector logic from both public rule modules;
- integrate both shells with the shared analyzer;
- convert only eligible records owned by that shell;
- update finding copy, remediation, docs, catalog, taxonomy confidence, tests,
  fixtures, inventory assertions, and report expectations;
- preserve both IDs, default scheduling, default `critical`, and normal config
  severity overrides;
- prevent duplicate findings when both presets are active;
- preserve inventory target `19 / 16 / 7 / 4`;
- keep both rules non-canonical FindingV2 rules.

Required finding copy:

- state that an exact Arc-deployed contract has a supported behavior dependency
  on PREVRANDAO, whose value is zero on Arc;
- identify the exact contract/function and supported sink class;
- recommend deterministic selection or an external randomness source appropriate
  to the application;
- state that analysis is static and Foundry-artifact-based;
- never claim live deployment or transaction success.

Required tests:

- wallet-only, bridge-only, both presets, explicit severity overrides, off,
  failOn, scoring, reporters, instrumentation, deterministic order, fixtures,
  demos, CLI, package smoke, and clean-repository checks;
- no duplicate finding for one private record;
- no finding for projects without exact Foundry Arc association;
- no finding from `mixHash`, comments, strings, broad Arc text, or unsupported
  Solidity flow.

Exit:

- independent review `APPROVE` with 0 blocker / 0 major / 0 minor.

### C09A-E5 — closeout

Scope:

- run final full repository verification;
- record merged phase commits and final inventory;
- document parser dependency and package impact;
- document supported grammar, Foundry-only coverage, unsupported surfaces, and
  compatibility-shell limitation;
- move C09 and C09A plans to completed;
- update roadmap and backlog;
- record later shell consolidation or retirement trigger.

Exit:

- final independent review `APPROVE` with 0 blocker / 0 major / 0 minor;
- CI, Repository Verification, Action Smoke, Example, candidate diff, and clean
  repository checks pass.

## 10. Risk controls

- separate E1 through E5 into independently reviewable PRs or commits;
- do not combine dependency introduction and public finding migration in one
  semantic phase;
- no force push or history rewrite;
- fail closed for every unsupported or ambiguous evidence dimension;
- preserve both public IDs until a later reviewed compatibility decision;
- never add a `solidity` preset or category in C09A;
- never import research prototypes directly into production;
- port behavior from reviewed contracts, not by copying research code without
  production review;
- no live RPC, explorer, compiler, or Foundry execution;
- stop and redesign if caching or shell routing requires a general plugin system;
- do not expand grammar from incidental implementation convenience.

## 11. Non-goals

C09A does not include:

- general Solidity CFG, SSA, taint, symbolic execution, or vulnerability
  analysis;
- arbitrary compiler-version inference;
- arbitrary imports, inheritance, libraries, modifiers, Yul, or cross-file value
  flow;
- Hardhat or custom deployment adapters;
- new public presets, categories, IDs, schemas, or plugin registries;
- canonical FindingV2 promotion;
- live-chain verification;
- C10 implementation.

## 12. Validation

Every semantic phase must run its focused tests plus:

```powershell
corepack pnpm exec prettier --check .
git diff --check
corepack pnpm verify:full
```

Dependency and public-integration phases must also verify:

```powershell
corepack pnpm pack
```

and run the packed package in a clean temporary project against:

- a non-Solidity repository;
- a supported Foundry Arc project;
- a Solidity project without exact Arc ownership;
- a project containing both wallet and bridge presets.

## 13. Completion contract

C09A is complete only when:

- both old keyword detectors are removed;
- one shared analyzer provides all source and ownership evidence;
- supported findings require exact source, sink, contract, Foundry artifact, and
  Arc chain evidence;
- each private record is owned by exactly one public shell;
- both public IDs remain compatible without duplicate findings;
- inventory remains `19 known / 16 default / 7 wallet / 4 canonical`;
- parser dependency and packed-package behavior are verified;
- no unsupported grammar or deployment adapter emits a finding;
- all semantic phases receive independent `APPROVE 0/0/0` reviews;
- full repository verification and product workflows pass;
- closeout evidence is recorded.

No production implementation begins before C09-D and this plan are independently
approved and merged.
