## 1. Decision

C08-R2 defines a deterministic corpus for one feasibility family only:

```text
CCTP V2 + direct global fetch + exact Iris host + same-file polling loop
```

The corpus does not authorize an analyzer. It gives C08-R3 a fixed set of source
shapes and independent evidence declarations with which to determine whether a
bounded, fail-closed analyzer is feasible.

The first family intentionally excludes:

- CCTP V1;
- Axios;
- imported endpoint or domain configuration;
- wrapper HTTP clients;
- helper polling functions called from another function;
- cross-file burn-result provenance;
- arbitrary URL construction;
- general control-flow or data-flow.

These exclusions are not claims that the excluded integrations are incorrect.
They are boundaries for the first feasibility test.

No final Build, Advice-only, or Retire disposition is selected by R2.

## 2. Source-shape observations

### 2.1 Circle documentation quickstarts

Current Circle Arc quickstarts use a direct global `fetch` inside `while (true)`
and a V2 messages URL containing the source domain and `transactionHash` query.
They delay and continue after a non-ready response and return after a complete
attestation is available.

This is the closest first-party shape to the first candidate family, but the
quickstart loop is unbounded and does not necessarily separate `429` from other
non-OK responses. It is a syntax seed, not a complete safe contract.

### 2.2 Circle maintained sample application

The Circle-maintained `circlefin/circle-cctp-crosschain-transfer` sample has a
realistic React hook shape:

- `retrieveAttestation(transactionHash, sourceChainId)` is a nested helper;
- `IRIS_API_URL` and `CHAIN_CONFIGS` are imported;
- the source domain is computed as
  `CHAIN_CONFIGS[sourceChainId].destinationDomain`;
- the URL is stored in a local binding;
- `while (true)` owns a direct global `fetch(url)`;
- exact `response.status === 404` delays and continues;
- another non-OK status throws;
- a complete body returns;
- other body states delay and repeat;
- no timeout or cancellation path is present;
- `429` has no dedicated branch.

This source confirms that imported configuration and computed domain ownership
are real usage, but those features exceed the first family. The sample is a
mandatory unsupported/pressure fixture rather than evidence that R3 should add
cross-file resolution.

### 2.3 Public integration shapes

Public CCTP integrations also exhibit these materially different shapes:

- bounded-attempt direct `fetch` loops;
- one-shot attestation requests that terminate on pending state;
- Axios loops that retry only `error.response.status === 404`;
- helpers that parse JSON before checking HTTP status;
- dynamic host selection and shared endpoint builders.

R2 records these shapes as corpus pressure. It does not normalize them into the
first candidate family.

## 3. Classification vocabulary

Every expanded fixture has exactly one expected research classification.

### `safe`

The complete source proves the exact first-family request and response ownership,
and all modeled pending states retry with a delay while `429`, unexpected
non-OK states, completion, and bounded exit are handled distinctly.

`safe` means only that the candidate source does not exhibit the proposed
control-flow defect. It does not prove runtime correctness, successful burn,
valid domain, valid transaction hash, API availability, or successful mint.

### `finding`

The complete source proves the exact first-family request and response ownership
and contains one exact unsafe control-flow action in the supported grammar.

A `finding` fixture is not derived merely from the presence of `404`, `throw`,
`return`, or another keyword. The evidence signature must first establish the
request, response, loop, and branch ownership.

### `unsupported`

The source is outside the bounded grammar or lacks sufficient ownership proof.
R3 must return no candidate and no finding for this class.

Unsupported silence is not a safety claim.

## 5. Canonical complete source

All single-mutation fixtures in section 7 expand from the following complete
TypeScript source. Replacement ranges are exact strings, applied once.

```ts
const SOURCE_CHAIN_ID = 5042002;
const SOURCE_DOMAIN_ID = 26;
const MAX_ATTEMPTS = 60;

async function pollArcAttestation(transactionHash: string) {
  const url =
    `https://iris-api-sandbox.circle.com/v2/messages/${SOURCE_DOMAIN_ID}` +
    `?transactionHash=${transactionHash}`;

  for (let attempt = 0; attempt < MAX_ATTEMPTS; attempt += 1) {
    const response = await fetch(url);

    if (response.status === 404) {
      await new Promise((resolve) => setTimeout(resolve, 5_000));
      continue;
    }

    if (response.status === 429) {
      await new Promise((resolve) => setTimeout(resolve, 10_000));
      continue;
    }

    if (!response.ok) {
      throw new Error(`Unexpected Iris status: ${response.status}`);
    }

    const body = await response.json();

    if (body.messages.length === 0) {
      await new Promise((resolve) => setTimeout(resolve, 5_000));
      continue;
    }

    const message = body.messages[0];

    if (message.status === "pending") {
      await new Promise((resolve) => setTimeout(resolve, 5_000));
      continue;
    }

    if (message.status === "complete" && message.attestation) {
      return message;
    }

    throw new Error(`Unexpected attestation state: ${message.status}`);
  }

  throw new Error("Attestation polling timed out");
}

void SOURCE_CHAIN_ID;
void pollArcAttestation;
```

Canonical signature:

```text
fileKind=ts
endpointVersion=v2-messages
irisHost=sandbox-literal
httpClient=global-fetch
urlOwnership=one-const-template
sourceChainOwnership=exact-arc
sourceDomainOwnership=one-const-paired-literal
transactionHashOwnership=direct-parameter
loopOwnership=direct-bounded-for
responseOwnership=direct-fetch-binding
statusModel=distinct-404-429-other
bodyModel=distinct-empty-pending-complete
retryDelayModel=direct-timeout-promise
boundedExitModel=attempt-limit
terminalActionModel=mixed
```

Canonical expected classification: `safe`.

The canonical source is deliberately stricter than the current Circle
quickstarts. It is a feasibility reference, not a recommendation that all
applications use exactly this code.

## 6. Complete standalone pressure fixtures

### R2-U01 — Circle maintained sample shape

```ts
import { CHAIN_CONFIGS, IRIS_API_URL } from "./chains";

const POLL_INTERVAL_MS = 5_000;

export async function retrieveAttestation(
  transactionHash: string,
  sourceChainId: number
) {
  const url =
    `${IRIS_API_URL}/v2/messages/` +
    `${CHAIN_CONFIGS[sourceChainId].destinationDomain}` +
    `?transactionHash=${transactionHash}`;

  while (true) {
    const response = await fetch(url);

    if (response.status === 404) {
      await new Promise((resolve) => setTimeout(resolve, POLL_INTERVAL_MS));
      continue;
    }

    if (!response.ok) {
      throw new Error(`Attestation request failed: ${response.status}`);
    }

    const body = await response.json();
    if (body?.messages?.[0]?.status === "complete") {
      return body.messages[0];
    }

    await new Promise((resolve) => setTimeout(resolve, POLL_INTERVAL_MS));
  }
}
```

Expected classification: `unsupported`.

Missing first-family proof:

- imported host;
- computed source domain;
- no separate `429` branch;
- complete-only body model;
- no bounded exit.

### R2-U02 — Axios 404 retry family

```ts
import axios from "axios";

export async function poll(url: string) {
  while (true) {
    try {
      const response = await axios.get(url);
      if (response.data.messages?.[0]?.status === "complete") {
        return response.data.messages[0];
      }
    } catch (error: any) {
      if (error.response?.status !== 404) throw error;
    }

    await new Promise((resolve) => setTimeout(resolve, 5_000));
  }
}
```

Expected classification: `unsupported`.

Missing first-family proof:

- Axios has different non-OK semantics;
- URL ownership is absent;
- domain and transaction-hash ownership are absent;
- no bounded exit;
- body states are incomplete.

### R2-U03 — CCTP V1 attestation family

```ts
export async function getAttestation(messageHash: string) {
  const response = await fetch(
    `https://iris-api-sandbox.circle.com/v1/attestations/${messageHash}`
  );
  if (!response.ok) throw new Error("Attestation request failed");
  const body = await response.json();
  return body.status === "complete" ? body.attestation : null;
}
```

Expected classification: `unsupported`.

Reason: V1 message-hash attestation semantics are a separate family.

### R2-U04 — one-shot V2 request

```ts
export async function getAttestation(
  sourceDomainId: number,
  transactionHash: string
) {
  const response = await fetch(
    `https://iris-api-sandbox.circle.com/v2/messages/${sourceDomainId}` +
      `?transactionHash=${transactionHash}`
  );
  if (!response.ok) throw new Error("Attestation unavailable");
  const body = await response.json();
  return body.messages?.[0] ?? null;
}
```

Expected classification: `unsupported`.

Reason: no polling-loop ownership or pending-state control flow is established.

### Exact finding cases

**R2-F01 — terminal throw on owned 404**

- Replace the complete `response.status === 404` body with:
  `throw new Error("Attestation failed");`
- Expected: `finding`
- Exact defect: proven pending-capable `404` is terminal immediately.

**R2-F02 — terminal return on owned 404**

- Replace the complete `404` body with: `return null;`
- Expected: `finding`
- Exact defect: proven polling flow exits on the first owned `404`.

**R2-F03 — break on owned 404**

- Replace the complete `404` body with: `break;`
- Expected: `finding`
- Exact defect: polling terminates before an attestation is available.

**R2-F04 — immediate 404 retry without delay**

- Remove the delay statement from the `404` branch and retain `continue`.
- Expected: `finding`
- Exact defect: tight retry loop for the owned expected-pending status.

**R2-F05 — 404 and 429 conflation**

- Replace both status branches with:
  `if (response.status === 404 || response.status === 429) {`
  followed by one five-second delay and `continue`.
- Expected: `finding`
- Exact defect: rate-limit handling is not distinct from ordinary pending
  polling.

**R2-F06 — empty messages terminal**

- Replace the empty-messages branch body with:
  `throw new Error("No attestation message");`
- Expected: `finding`
- Exact defect: a documented not-yet-processed V2 state is terminal.

**R2-F07 — pending body terminal**

- Replace the pending branch body with:
  `return null;`
- Expected: `finding`
- Exact defect: a documented pending message exits the polling flow.

**R2-F08 — complete body ignored**

- Replace the complete branch body with a delay and `continue`.
- Expected: `finding`
- Exact defect: a ready attestation never exits the bounded polling flow.

**R2-F09 — unexpected status silently retried**

- Replace the `!response.ok` throw with a delay and `continue`.
- Expected: `finding`
- Exact defect: unexpected non-OK responses are conflated with pending states.

**R2-F10 — timeout removed**

- Replace the bounded loop with `while (true)` and remove the final timeout
  throw.
- Expected: `finding`
- Exact defect: no bounded exit remains in an otherwise supported direct flow.

## 8. Corpus counts and invariants

The corpus contains:

- 1 canonical safe source;
- 4 complete standalone pressure fixtures;
- 8 safe single-mutation cases;
- 10 finding single-mutation cases;
- 26 unsupported single-mutation cases.

Total declared cases: **49**.

Required invariants:

1. Every case expands to one complete source file.
2. Every mutation is deterministic and applies exactly once.
3. Evidence metadata is declared before expected classification is checked.
4. A finding requires all first-family ownership evidence.
5. Missing or conflicting ownership always yields `unsupported`, never `safe`.
6. Unsupported silence is never described as correctness.
7. No fixture performs a live Circle request.
8. V1 and Axios cases cannot be promoted into the first family by substring
   similarity.
9. Arc domain `26` applies only when Arc is the proven source chain; it is not a
   universal domain for transfers whose source is another chain.
10. The official Circle sample remains unsupported until imported configuration,
    computed domain ownership, and unbounded-loop policy receive separate review.

## 9. R3 feasibility questions

R3 must answer these questions using the fixed corpus:

1. Can TypeScript AST analysis prove direct global `fetch` identity without a
   generic HTTP abstraction?
2. Can exact Iris host and V2 path ownership be recognized for direct and one
   immutable URL binding only?
3. Can source-chain/domain pairing be proven from a small explicit literal map
   without duplicating the entire CCTP domain catalog?
4. Can one parameter and one immutable binding establish transaction-hash
   ownership without claiming the hash came from a successful burn?
5. Can direct loop, response, status, body, and action ownership be proven without
   general CFG or SSA?
6. Can direct timeout-promise delays and one bounded-exit form be recognized
   conservatively?
7. Can every unsupported case fail closed with no candidate?
8. Does the supported family cover enough meaningful usage to justify a critical
   rule, given that Circle's maintained sample is outside the first grammar?

Question 8 is a product gate, not merely a parser gate. A technically feasible
analyzer with negligible real-world coverage should lead to Advice-only or
Retire rather than Build.

## 11. Conclusion

C08-R2 is complete when this corpus receives independent review.

The recommended next step is C08-R3: a private, disposable feasibility prototype
against the fixed 49-case corpus. R3 must not modify the public rule, tests,
severity, preset membership, catalog, schemas, reporters, scoring, CLI behavior,
or canonical FindingV2.

If R3 cannot satisfy the bounded ownership contract without generic control-flow,
data-flow, imported configuration, or cross-file resolution, it must recommend
Advice-only or Retire rather than broadening the prototype.
