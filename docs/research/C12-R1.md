# C12-R1 — NO_ETH_GAS_LABEL Advice-Only Migration Research

Status: Approved architecture evidence

Risk: R3 default-selection, severity, scoring, and exit-behavior migration

Base branch: `main`

Base SHA: `1b0145146ac7f539fcb280d5539f1d8a68560ca6`

Research branch: `research/c12-no-eth-gas-label-advice`

Last reviewed: 2026-08-20

## 1. Product problem and why now

`wallet/NO_ETH_GAS_LABEL` is a default critical file-level regex. It claims an
Arc wallet fee UI appears to label fees as ETH or Gwei whenever one Arc-related
file contains a matching line. The detector does not prove that the line is a
rendered label, belongs to the Arc UI, or misstates the fee denomination.

The C11 adoption audit scanned eight pinned public repositories. ArcLens
received seven critical findings and score zero from this rule alone. Six files
were definite false positives and the seventh was mixed. This is measured
default-CI harm, not a theoretical unsupported syntax request.

The backlog already selected `Advice-only`. C12 researches and specifies the R3
runtime migration for that existing decision.

## 2. First-party premise

Current Arc documentation was checked on 2026-08-20:

- `https://docs.arc.io/integrate/wallets/fee-display` says wallet UI should show
  fees as USD amounts rather than Gwei or ETH;
- the same page uses Gwei for base-fee parameters, internal calculations, and
  worked examples;
- `https://docs.arc.io/integrate/exchanges/custody` uses Gwei for minimum base
  fee, EIP-1559 transaction parameters, and operational fee estimation while
  requiring USDC as the native asset and fee token.

The product premise is therefore narrower than the detector:

```text
wrong rendered wallet denomination is actionable
≠
any fee/gas plus ETH/Gwei line co-located in a file containing Arc evidence
```

Gwei is valid internal EVM fee-unit terminology on Arc. ETH is also valid in
correct contrasts, compatibility explanations, and non-Arc sibling content.
Critical enforcement requires rendered-UI ownership that the current detector
does not establish.

## 3. Repository baseline

Current runtime behavior:

- `noEthGasLabelRule` is publicly exported and retained in public
  `walletRules`;
- `defaultPresetRegistry` uses all of `walletRules`, so normal wallet scans
  schedule it;
- exported `getRulesForPresets(["wallet"])` and `defaultPresetRegistry` expose
  that default scheduling behavior;
- direct/default severity is `critical`;
- `config.rules[id]` can override severity or turn the already-selected rule
  off;
- the rule is non-canonical and does not enter FindingV2/`json-v2`;
- catalog policy still says experimental compatibility, required change,
  prototype, and default-enabled even though the backlog says Advice-only.

The repository already has a reviewed default-excluded advice mechanism for
`bridge/ATTESTATION_404_NOT_FATAL`:

- public known inventory remains available;
- a private default subset excludes the rule;
- a private deterministic known-rule registry allows explicit `info`,
  `warning`, or `critical` selection;
- missing, `off`, and unknown configuration remain non-selecting;
- custom preset registries do not inherit built-in excluded rules.

No new public API or general rule registry is needed for C12.

## 4. Adoption finding classification

The seven ArcLens findings came from 151 discovered source files.

Definite false-positive classes include:

- correct contrast copy such as gas paid in USDC, not ETH;
- explanatory copy that Arc requires no ETH exposure;
- AI/tool descriptions that correctly state USDC pays gas;
- a rendered base-fee value in Gwei alongside a dollar-denominated cost;
- internal gas-price variables and calculations colocated with Arc UI text.

One file also contains an `ETH Transfer` example that may merit human review,
but the file-level finding cannot identify whether that phrase or valid Gwei
calculation caused the result. It cannot support a critical corrective action.

## 6. Options considered

### A. Keep default execution and only change severity

Rejected. Seven unsupported file-level findings would still appear in ordinary
reports, lower score, and create warning/info noise. This does not implement an
optional Advice-only posture.

### B. Patch the regex around current ArcLens phrases

Rejected. Adding `not ETH`, special-casing Gwei, or narrowing strings does not
prove rendered UI ownership. It would optimize for one corpus while preserving
the same architecture defect.

### C. Build a rendered-UI analyzer now

Deferred. A truthful blocker would need to prove framework-specific render
sinks, Arc ownership, exact visible text/value flow, and sibling isolation.
That is a different analyzer milestone and has no repeated supported pattern or
approved contract yet.

### D. Retire the public rule immediately

Rejected for this compatibility period. The official UI guidance is valid and
the public rule ID may still be useful as explicitly requested low-confidence
advice.

### E. Reuse the existing default-excluded advice path

Selected. It implements the existing Advice-only decision, removes default-CI
harm, preserves a narrow compatibility opt-in, and requires no new external
configuration or registry abstraction.

## 7. Architecture candidate

### 7.1 Known/default wallet split

Keep `walletRules` and the public `noEthGasLabelRule` export unchanged as known
inventory. Add a private `walletDefaultPresetRules` subset that excludes exactly
`wallet/NO_ETH_GAS_LABEL`, and use that subset only in
`defaultPresetRegistry`.

### 7.2 Existing explicit selection path

Append `noEthGasLabelRule` to the existing private `defaultExcludedRules` list
after `attestation404NotFatalRule`. Keeping the existing entry first preserves
its observable selection order. The top-level `getRulesForScan` semantics and
signature remain unchanged.

Explicit `info`, `warning`, or `critical` selects the rule exactly once. Missing
or `off` does not select it. Unknown rule IDs remain inert. Explicit selection
does not require the wallet preset because naming the known ID is the ownership
of the opt-in decision, matching C08A behavior.

### 7.3 Advisory rule contract

Keep the detector implementation unchanged. Do not add phrase exceptions.

Change direct/default severity to `info`. Finding copy must state only that a
file containing coarse Arc evidence also contains a gas/fee phrase for review.
It must not claim the phrase itself belongs to Arc or that ArcReady proved a
rendered UI defect. Remediation must say:

- if the phrase is user-facing Arc fee display, show USDC/USD;
- Gwei may remain valid for internal gas-price units and calculations;
- correct contrasts, documentation, and non-Arc content may be ignored.

Approved copy candidate:

```text
description: Provides low-confidence advice when a file with Arc evidence also contains a gas or fee line mentioning ETH or Gwei.
message: Gas or fee text mentioning ETH/Gwei is co-located in a file with Arc evidence; review whether the text is a user-facing Arc fee label.
remediation: If this text is rendered to Arc wallet users, display the fee in USDC or USD. Gwei remains valid for internal gas-price units and calculations; correct contrasts, documentation, and non-Arc content may not require changes.
```

Explicit-info regression must include the unsupported multichain sibling:

```ts
export const arcTestnet = { id: 5042002 };
export const ethereumGasFee = "Ethereum network fee: 0.01 ETH";
```

The unchanged heuristic may emit one opted-in review record, but copy and
remediation must preserve that the matched line may be non-Arc sibling content.

### 7.4 Policy metadata

Align runtime and documentation catalogs to:

```text
taxonomy=advice
impact=recommendation
maturity=deprecated
recommendedDefaultEnabled=false
recommendedCiFailureEligible=false
deprecated=true
```

The documentation catalog must label the rule default-excluded and show an
explicit `info` opt-in. The public ID remains available for one compatibility
period before a separately evidenced Retire review.

### 7.5 External boundary impact

Intended changes:

- ordinary wallet scans no longer schedule the rule;
- exported `getRulesForPresets(["wallet"])` and `defaultPresetRegistry` return
  the new default subset without the rule;
- default known-rule execution inventory decreases by one while known wallet
  inventory and public exports remain unchanged;
- default reports, score, status, `failOn`, and process exit no longer depend on
  this heuristic;
- explicit configured levels remain authoritative and preserve legacy detector
  matching;
- direct/custom execution defaults to `info`;
- canonical runtime, FindingV2, schemas, reporters, dependencies, and package
  exports do not change.

The executable inventory boundary becomes `19 known / 15 default / 7 known
wallet / 6 default wallet / 4 canonical`.

## 8. Stop conditions

Stop and redesign if:

- selecting the second excluded rule requires exporting or generalizing the
  private registry;
- default exclusion changes public `walletRules` or removes the rule export;
- explicit opt-in cannot remain deterministic and isolated from custom
  registries;
- the migration requires detector widening, a JSX analyzer, schema changes, or
  FindingV2 support;
- a default fixture change cannot be traced solely to removal of this rule.

## 9. Research conclusion

Proceed with a bounded R3 Advice-only migration using the already-reviewed C08A
selection architecture. Do not harden the regex and do not claim rendered UI
analysis. Architecture review must approve the second-consumer ordering,
inventory delta, explicit selection contract, copy, and scoring/exit impact
before production changes.
