# ArcReady v0.3.0 Demo Recording Guide

## Demo objective

Record a practical 60-90 second demo that shows ArcReady as an open-source Arc-specific static CI quality gate and integration-pattern validator.

The demo should make three points clear:

- Arc integrations can break from small config and assumption mistakes.
- ArcReady catches common static integration patterns before release.
- ArcReady is easy to run locally or in CI with `arcready@0.3.0` and `tanka420/arcready@v0.3.0`.

## Recommended video length

Target 60-90 seconds.

Suggested pacing:

- 10 seconds: problem
- 15 seconds: what ArcReady is
- 25 seconds: local CLI demo
- 15 seconds: report and GitHub Action demo
- 10 seconds: scope and CTA

## Recording setup

- Use a clean terminal with readable font size.
- Open the ArcReady README in the browser or editor.
- Use `examples/demo-projects/broken-arc-integration` as the starting project.
- Use `examples/demo-projects/fixed-arc-integration` as the corrected reference state.
- Keep browser/editor tabs minimal: README, terminal, flagged files, fixed reference, GitHub Action snippet.
- Avoid showing secrets, personal tokens, or private repo data.

## Terminal preparation

Start from a temporary working directory so the recording shows a realistic repair workflow without editing the checked-in example.

Before recording:

- clear the terminal
- make sure Node.js 22+ is available
- make sure internet access is available for `npx`
- optionally remove any old `arcready-report.md` or `arcready-report.html`
- copy `examples/demo-projects/broken-arc-integration` into the temporary working directory

## Demo project roles

Both demo projects are intentionally kept in the repository:

- `broken-arc-integration` is the realistic starting point with wallet, bridge, and App Kit integration mistakes.
- `fixed-arc-integration` is the corrected reference state for the same integration ideas.

The launch video should use them as before/after states in one repair workflow: scan the broken copy, inspect the findings, fix the flagged files by matching the fixed reference, then scan again until ArcReady passes.

## Scene-by-scene script

1. Problem: "Arc integrations can fail because of small configuration and assumption mistakes."
2. Product: "ArcReady is an open-source Arc-specific static CI quality gate for wallet, bridge, and App Kit integration patterns."
3. Local demo: Copy the broken demo project into a temporary working directory and run a scan.
4. Repair: Open the flagged wallet, bridge, App Kit, and config files, then apply the fixed reference patterns.
5. CI demo: Show GitHub Action usage with `tanka420/arcready@v0.3.0`.
6. Scope: Clarify static checks only.
7. CTA: Try it with `npx` or add it to CI.

## Exact terminal commands

Recommended demo commands from the repository root:

```powershell
$demoRoot = Join-Path $env:TEMP "arcready-v030-demo"
Remove-Item -LiteralPath $demoRoot -Recurse -Force -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Path $demoRoot | Out-Null
Copy-Item -Recurse examples/demo-projects/broken-arc-integration (Join-Path $demoRoot "arc-integration")
Set-Location (Join-Path $demoRoot "arc-integration")
npx --yes arcready@0.3.0 scan
```

Open and repair the flagged files:

```text
src/wallet/arc-wallet.ts
src/bridge/cctp-bridge.ts
src/app-kit/app-kit.ts
arcready.config.json
```

Use this checked-in project as the corrected reference:

```text
examples/demo-projects/fixed-arc-integration
```

Then run the scan again:

```powershell
npx --yes arcready@0.3.0 scan
```

GitHub Action usage:

```yaml
- uses: tanka420/arcready@v0.3.0
```

## GitHub Action segment

Show this minimal snippet:

```yaml
jobs:
  arcready:
    runs-on: ubuntu-latest
    permissions:
      contents: read

    steps:
      - uses: actions/checkout@v4

      - uses: tanka420/arcready@v0.3.0
        with:
          fail-on: critical
```

Voiceover:

"The GitHub Action runs the published npm CLI and defaults to `arcready@0.3.0`. It can upload JSON, Markdown, and HTML reports as CI artifacts."

## Scope disclaimer

ArcReady is a static developer-side release check. It does not perform:

- live Arc RPC checks
- Circle API checks
- on-chain transaction simulation
- contract deployment validation
- bridge runtime simulation
- real App Kit runtime validation
- SaaS/dashboard monitoring

ArcReady is an independent open-source project. It is not an official Circle or Arc product.
